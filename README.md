# JP_ALL: 일본 전 종목 공시 채널 봇 설치 안내

도쿄증권거래소 TDnet에 올라오는 모든 적시공시를 한국어로 텔레그램 채널에 하나씩 올립니다. 실행은 GitHub Actions(무료)에서 하므로 컴퓨터를 켜 둘 필요가 없습니다.

## 게시 예시
```
2026.09.24 15:30
기업명: 아스카 7227 [나고야]
보고서명: FY11/26 3Q 결산단신〔일본 기준〕(연결)

[3Q 단독 · 6~8월 · 연결]
매출액 : 116억 (YoY +3.6% · 예상치 110억 / +5%)
영업익 : 5.2억 (YoY -2.5%)
경상익 : 6.3억 (YoY +19.3%)
순이익 : 4.1억 (YoY +13.5%)
EPS : 72.4엔 (예상치 80.0엔 / -9%)
예상치: Yahoo Finance 애널리스트 평균(매출 3명·EPS 2명)

[누적 3Q · 25.12~26.08 · 연결]
매출액 : 351억 (YoY +2.3%)
...
회사 가이던스(FY11/26) : 매출 470억 / 영업익 22.0억 / ...
영업익 진척률 : 80% (누적 3Q 기준)

최근 분기 실적 추이 (매출/ 영업익/ 순이익)
26.06-08 116억/ 5.2억/ 4.1억 (이번)
26.03-05 116억/ 7.0억/ 4.5억
...
공시링크: https://www.release.tdnet.info/inbs/....pdf
회사정보: https://kabutan.jp/stock/?code=7227
```
위 예시의 컨센서스 값(110억, 80.0엔)은 형식을 보여 주려고 넣은 가상 값입니다. 금액 단위는 모두 억엔입니다.

## 공시 종류별 내용
| 공시 | 본문에 붙는 내용 |
|---|---|
| 결산단신(1Q~4Q) | 분기 단독 실적과 YoY, 컨센서스 대비(있을 때), 누적 실적, 회사 가이던스와 진척률, 최근 5개 분기 추이. 4Q에는 다음 기 가이던스의 증감률도 붙습니다 |
| 실적 전망 수정 | 매출·영업익·경상익·순이익·EPS의 수정 전 → 후와 변화율 |
| 배당 전망 수정 | 연간 주당배당 수정 전 → 후, 전기 실적 |
| 자사주 취득 결정 | 한도 주식 수(비율), 금액, 기간 |
| 공개매수(TOB·MBO) 개시·의견표명 | 매수가격, 프리미엄, 기간 |
| 그 밖의 공시 | 날짜, 기업명, 번역 제목, 링크 |

ETF·ETN의 일일 공시(하루 수십 건, 내용 없음)는 올리지 않습니다.

## 설치 (약 15분)

### 1. 봇을 채널 관리자로 추가
1. 텔레그램에서 JP_ALL 채널을 열고 **채널 정보 → 관리자 → 관리자 추가**를 누릅니다.
2. `@JP_all_yh_bot`을 검색해서 추가하고, **메시지 게시** 권한을 켭니다.

### 2. 봇 토큰 준비
@BotFather에서 `/mybots` → JP_all_yh_bot → **API Token**을 누르면 토큰이 나옵니다. 이 토큰은 채팅 등 다른 곳에 붙여넣지 말고, 4단계의 GitHub 화면에만 넣으세요.

### 3. 채널 ID 확인
- **공개 채널**이면 `@채널아이디`(예: `@JP_ALL`)를 그대로 씁니다. 채널 정보의 링크 `t.me/...` 뒷부분이 아이디입니다.
- **비공개 채널**이면 `-100`으로 시작하는 숫자를 씁니다. 찾는 방법:
  1. 채널에 아무 글이나 하나 올립니다.
  2. 브라우저에서 `https://api.telegram.org/bot[토큰]/getUpdates`를 엽니다.
  3. 결과에서 `"chat":{"id":-100…` 숫자를 복사합니다.

### 4. GitHub 저장소 만들기
1. https://github.com 에 가입하거나 로그인합니다.
2. 오른쪽 위 **+ → New repository**를 누르고, 이름을 `jpall`로 합니다. **Public**을 선택하고 **Create repository**를 누릅니다. Public이어야 Actions가 무료로 무제한 돌아갑니다. 코드에는 비밀값이 없고, 토큰은 5단계의 Secrets에만 들어갑니다.
3. 저장소 화면의 **uploading an existing file**을 누릅니다. 받은 zip을 푼 폴더 안의 파일과 폴더를 **전부** 끌어다 놓습니다(`.github` 폴더 포함). 그다음 **Commit changes**를 누릅니다.
   - `.github` 폴더는 숨김 폴더라서 맥 Finder에서 안 보일 수 있습니다. Finder에서 `Cmd+Shift+.`를 누르면 보입니다.
   - 끌어 놓기가 안 되면 **Add file → Create new file**을 누르고, 파일 이름에 `.github/workflows/jpall.yml`을 입력한 뒤 그 파일 내용을 붙여넣어도 됩니다.

### 5. 비밀값 넣기
저장소에서 **Settings → Secrets and variables → Actions → New repository secret**을 눌러 두 개를 넣습니다.
- `TELEGRAM_TOKEN`: 2단계의 봇 토큰
- `CHANNEL_ID`: 3단계의 채널 ID(`@JP_ALL` 또는 `-100…`)

### 6. 실행
1. 저장소의 **Actions** 탭에서 워크플로 사용 동의 버튼이 보이면 누릅니다.
2. 왼쪽 **JP_ALL → Run workflow**를 누르면 바로 시작합니다. 그 뒤로는 10분마다 자동으로 이어서 실행됩니다.
3. **첫 실행**은 그날 이미 나온 공시를 게시하지 않고 기록만 합니다. 그 뒤 새로 나오는 공시부터 채널에 올라옵니다.

## 동작 방식
- 한 번 실행하면 약 28분 동안 1분마다 TDnet을 확인하고 새 공시를 올립니다. 10분마다 다음 실행이 대기하므로 거의 끊기지 않고 이어집니다.
- 이미 올린 공시 기록은 저장소의 `state` 브랜치에 자동으로 저장됩니다. 이 브랜치는 지우지 마세요.
- 컨센서스는 발표 4일 전부터 Yahoo Finance 애널리스트 추정치를 미리 저장해 두었다가 씁니다. 발표 후에는 다음 분기 추정치로 바뀌기 때문입니다.

## 알아 둘 점
- **게시 지연:** 텔레그램은 채널당 분당 약 20건까지만 올릴 수 있어 3.3초 간격으로 올립니다. 결산 시즌 15:00~15:30에 수백 건이 몰리면 마지막 공시는 수십 분 늦게 올라갈 수 있습니다. 또 GitHub의 예약 실행은 붐빌 때 몇 분 늦게 시작되기도 합니다.
- **컨센서스 범위:** Yahoo에 애널리스트 추정치가 있는 종목만, 매출과 EPS만 나옵니다. 일본 애널리스트가 주로 보는 영업이익 컨센서스는 무료로 구할 곳이 없어서, 대신 회사 가이던스 대비 진척률을 보여 줍니다. 봇 설치 전에 발표 일정이 잡힌 종목은 첫 며칠 동안 컨센서스가 비어 있을 수 있습니다.
- **분기 단독 실적:** 결산단신은 누적 수치만 싣기 때문에, 이전 분기 실적(가부탄 분기 실적표)을 빼서 계산합니다. 가부탄에 이전 분기가 없는 신규 상장 종목 등은 분기 단독 없이 누적만 나옵니다.
- **본문 없이 제목만 나가는 경우:** REIT 결산, 정정 공시, 서식이 특이한 PDF(자사주·TOB)는 수치 없이 제목과 링크만 올라갑니다.
- **나고야·후쿠오카·삿포로 단독 상장 종목:** 시가총액이 표시되지 않을 수 있습니다.
- **번역:** 제목은 Google 번역 공개 주소로 옮기고 자주 쓰는 용어(자사주, 실적 전망, 공개매수 등)를 보정합니다. 번역이 실패하면 일본어 원문이 나갑니다.
- **링크:** TDnet PDF 링크는 공시 후 약 1개월이 지나면 열리지 않습니다.
- **예약 실행 자동 중지:** GitHub는 공개 저장소에 60일 동안 활동이 없으면 예약 실행을 멈춥니다. 봇이 `state` 브랜치에 계속 기록하므로 보통은 괜찮지만, 멈추면 Actions 탭에서 **Enable workflow**를 누르면 됩니다.
- **이용 약관:** GitHub Actions는 원래 코드 빌드·테스트용이라, 상시로 돌리는 봇은 약관상 문제가 될 수 있습니다. 가부탄과 Yahoo 데이터를 공개 채널에 가공해 올리는 것도 각 사이트 약관과 부딪힐 수 있습니다. 채널을 비공개나 소수 공유로 운영하면 위험이 줄어듭니다.

## 문제 해결
- **게시가 안 될 때:** Actions 탭에서 실행 기록을 열고 **공시 게시** 단계의 로그를 봅니다. `telegram error 403`이 보이면 봇이 채널 관리자가 아닌 것이고, `400 chat not found`이면 CHANNEL_ID가 틀린 것입니다.
- **처음부터 다시 시작:** 저장소에서 `state` 브랜치를 지우면, 다음 실행이 첫 실행처럼 기록만 하고 다시 시작합니다.
- **멈추기:** Actions → JP_ALL → 오른쪽 위 `…` → **Disable workflow**를 누릅니다.
